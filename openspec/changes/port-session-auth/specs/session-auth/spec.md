## ADDED Requirements

### Requirement: 统一站点网络会话
应用 SHALL 使用每站点独立 Session 完成登录后的搜索、图片与下载，保持 Cookie 和 Referer 一致；代理优先使用单站点配置，否则继承全局设置。

#### Scenario: 切换代理
- **WHEN** 用户更改全局或单站点代理
- **THEN** 新请求使用新配置，旧连接被释放；非法输入不修改已保存的有效设置，代理失败不自动直连

### Requirement: 隔离网页登录
应用 MUST 在无 Node、无应用 preload 的隔离远程视图展示登录页；只有本地登录工具栏可触发验证。用户关闭或验证失败 SHALL 不保存未验证凭据。

#### Scenario: 认证与恢复
- **WHEN** 用户在站点完成登录并点击验证按钮
- **THEN** 主进程验证凭据和服务端结果，成功后持久化到站点 Cookie 存储；本地 UI 仅收到登录状态，重启可恢复，注销清理该站点会话

#### Scenario: 验证中关闭
- **WHEN** 验证或 Cookie 提交期间用户关闭登录窗口
- **THEN** 中断验证并避免保存部分凭据，不报告认证成功

### Requirement: 源 UI 与静态作品链路
应用 SHALL 沿用源账号入口、登录窗口布局、代理控件以及 Pixiv 分类；支持首个需登录站点的静态浏览与下载，未迁移动图功能明确反馈。

#### Scenario: 已登录浏览
- **WHEN** 用户搜索 Pixiv 静态作品并预览或下载组图
- **THEN** 使用同一站点会话获取列表与详情，遵循图片质量和组图下载设置，不把鉴权失败当作空结果

### Requirement: 可复核验收
实现 MUST 提供会话隔离、代理路由、Cookie 持久化、无权限远程页面和本地 UI 的验证证据。

#### Scenario: 阶段完成
- **WHEN** 汇报本阶段结果
- **THEN** 区分模拟环境通过、真实站点可访问和真实账号登录通过，不记录凭据，不自动进入下一阶段
