## Goals / Non-Goals

**Goals:**
- 按原 UI 与行为完成 Konachan-G 搜索到预览的闭环。
- 每项验收可定位源代码；对已读、过滤和命名字段等语义使用同输入对照。
- Windows 运行验证和画面对照；macOS 保留兼容实现与待验证记录。

**Non-Goals:**
- 下载执行、账号登录、全站点适配、完整设置面板和安装包属于后续阶段。
- 不对原界面做审美重设计，不因技术栈不同擅自删改功能。

## Decisions

1. **首站 Konachan-G。** 原代码已有独立站点入口，使用 JSON，适合验证完整浏览路径。相比一次迁移全部 Booru，单站点能逐项确认分页和字段；网络可用性不是已知事实，实施时测试。
2. **沿用 HTML/CSS/TypeScript。** 先按窗口与控件职责拆分普通模块，用源资源和 CSS 复现布局。暂不增加 React/Vue 或主题组件库；现有工具能完成本阶段，没有现成源 Web 组件可复用。
3. **业务请求在主进程。** preload 只暴露当前用到的搜索、取消、提示、预览及复制等方法；检查调用方、参数与数据大小。渲染端不传任意文件路径或任意请求 URL。
4. **图片按搜索结果中的条目标识获取。** 主进程验证图片 URL、重定向与响应类型，通过受限图片协议或显式数据传输交给渲染端；不开放通用 HTTP 代理，不一次把全部原图转成 base64 常驻内存。具体 Electron API 在实现前核对。
5. **状态语义对齐源项目。** 搜索请求带会话标识，取消或后续搜索后不插入过期结果。条目保留 ID、标签、作者、日期、评级、分数、分辨率、图源、缩略图/预览图/原图 URL；缺失字段处理按原逻辑验证。
6. **预览使用独立 BrowserWindow。** 不改成页面内灯箱；鼠标滚轮单位转换后对照源缩放结果，拖动限制和 Escape 保持原行为。
7. **保留后续功能入口的空间与视觉。** 尚未实现的操作明确提示未完成，并进入差异清单；不伪造下载、登录或设置成功。此阶段差异不代表项目最终删减。
8. **补齐原版材质和控件。** 当前 Windows 10 不支持 Electron 内建的 Windows 11 背景材质接口，使用 Koffi 作为有限的原生调用桥接，按 FluentWPF `AcrylicHelper` 设置本应用窗口。噪点及许可证复用原包资源；页面无法调用任意原生函数。自绘下拉框、数字调节器和状态样式按源 XAML 实现。
9. **条目实例与站点 ID 分开。** 分页结果允许重复站点 ID；主进程为每条结果分配会话内独立键，供卡片选择、图片协议、预览和进度使用。站点 ID 保持原语义，不通过去重隐藏条目。

## Risks / Trade-offs

- 源目录仍在变化 → 实施开始时保存相关文件的 SHA-256 和基线说明；变化时核对，不混用不同版本。
- WPF 透明效果、字体度量和原生窗口行为存在平台差异 → 同尺寸、缩放和设置下截图对照；不能复现的差异提交 review。
- 源站失效或网络限制 → 分开记录本地样本验证和在线验证；不把样本通过标成在线通过。
- 源行为存在缺陷 → 保留对照证据，确需变更时列出差异，不能直接“优化”掉原语义。
- 后续能力入口暂不可用 → 在阶段范围与验收中明确，不宣称全功能迁移完成。

## Migration Plan

1. 记录源基线、运行画面和设置；检查测试所需资源来源，保留许可证与署名。
2. 替换占位页，逐个接入搜索、列表与预览；未通过检查前不标完成。
3. 保留第一阶段隔离与失败退出码回归检查，调整仅针对占位文案的断言。
4. 阶段完成后提交对照结果供 review，不自动进入下载阶段。回退用版本控制，不修改源项目。
