# MoeLoaderE 路线图

## 目标与决策

- 将 MoeLoaderP 换语言等价转写：逻辑、UI 布局、样式、文案和交互保持一致，不重新设计产品。
- 已确定：Electron + TypeScript；不保留 C# 运行时。
- 目标平台：Windows、macOS 桌面端；Linux 暂不考虑。移动端与 Web 版另行评估。
- 主进程负责站点请求、会话和文件操作；渲染进程负责界面。实际需要通信时才添加明确、受限的 preload API。
- 登录页使用隔离的浏览器上下文，不开放 Node 权限；站点请求与下载需统一 Cookie、代理和 Referer。
- 初版使用本地 JSON 保存设置；不预建数据库、插件框架、通用任务系统。
- 站点逐个验证；旧版存在实现不等于接口仍可用。

## 等价迁移约束

- 2026-09-15 用户明确要求逻辑与 UI 保持源项目一致；此要求优先于此前关于重做界面的表述。
- 基线：`D:\code\MyGit\MoeLoaderP` 当前工作区，包含未提交修改；当前 HEAD 为 `f37c511`。
- 当前未提交源码涉及 `MoeDownloader.cs`、`MoeItem.cs`、`SearchSession.cs`、`zh-CN.xaml`、`DownloaderControl.xaml` 及其 code-behind、`MoeExplorerControl.xaml.cs`；另有未跟踪 `specs/`。不能只按 HEAD 的旧实现迁移。
- 每个功能开始前读取对应源文件，追踪入口、状态和异常路径；源工作区若变化，在当前 spec 记录基线变动。
- UI 对照源窗口运行画面、XAML、资源与事件处理：布局、颜色、字体、图标、菜单、快捷键、框选、分页、预览、设置和状态反馈逐项验收。
- 逻辑使用相同输入或本地样本对照输出：站点参数、解析、排序过滤、命名、重复文件处理、队列状态与重试、登录和代理。失效外部站点单独记录，不以联网失败替代逻辑验收。
- 每个阶段 review 附本阶段源功能清单、已转写项、截图或行为验证结果、未完成项及差异。
- 平台不支持的效果或系统行为、源代码缺陷及确需调整的行为单独列为差异，在 review 中确认；不默默删减或改成另一种交互。
- 当前阶段 1 页面仅为开发占位页，尚未完成任何正式 UI 的一致性验收。

## 跟踪规则

- 本文件记录总体进度；当前功能的 spec 记录实施任务、关键决策和验收证据。
- 小范围改动用 speclite；跨 3 个以上独立模块的变更按 speclite 约定转 OpenSpec，不将整个项目塞进一个 spec。
- 每次只细化当前阶段；阶段不是必须由一份 spec 完成的任务。
- spec 确认后再实现；开始或恢复实现前重新读取最新 spec。
- 每阶段完成并验证后停止，提交阶段结果供用户 review；用户确认继续后才进入下一阶段。
- 已实现、已验证分别记录；验证失败或缺少目标平台环境时保持未完成。
- 不在进度文档记录账号、Cookie、令牌或其他登录凭据。
